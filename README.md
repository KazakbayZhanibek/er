# Kompas — сайт

Испаноязычная версия сайта кадровой компании: собственный найм и подбор сотрудников для других работодателей. Географическая привязка к Испании удалена по уточнению заказчика от 2026-11-22. Пользователь выбрал визуальное направление №3: песочный фон, терракота, крупная редакционная типографика и широкая фотография.

Уточнение заказчика: при собственном найме работодателем выступает «Компас». При подборе в другие компании условия зависят от этой компании и обсуждаются с кандидатом индивидуально. Значение формулировки об оформлении после испытательного срока ещё уточняется; на сайте срок оформления и тип договора не заявлены.

## Что реализовано

- Адаптивная главная страница, навигация и мобильное меню.
- Основной сценарий для соискателя: вводные видео сразу после первого экрана, поиск работы и бланк заявки. Для работодателей — компактный отдельный блок в самом низу страницы и ссылка в подвале.
- Отдельные бланки для соискателя и работодателя с проверкой полей, просмотром и редактированием данных.
- Общие заявки по всей Испании, требование знания испанского, индивидуальные условия и общение с менеджером через переводчика.
- Раздел о компании и два готовых вводных видео с управлением воспроизведением, встроенными испанскими субтитрами и текстом озвучки.
- Монограмма K, испанский интерфейс, часы работы 9:00–18:00 по Мадриду и согласованный срок связи 24 часа.
- Локальные шрифты, библиотека иконок Phosphor и оптимизированные WebP-изображения.
- Поддержка клавиатуры и уменьшения анимации.

Адрес получателя заявок подтверждён заказчиком 2026-11-22 и хранится только в локальной переменной/секрете Cloudflare, а не в открытом репозитории. Пока Worker и Resend не развёрнуты с рабочими секретами, опубликованные формы остаются в режиме предпросмотра: данные не отправляются и не сохраняются. Подготовлен отдельный Cloudflare Worker: после настройки он сохраняет заявку в D1, передаёт письмо через Resend, повторяет временно неудавшуюся отправку и отправляет кандидату согласованное подтверждение на испанском. Для соискателя обязательны имя, email и короткое сопроводительное письмо; телефон, город и область интереса необязательны. Работодатель указывает компанию и потребность в сотрудниках. Используются общие заявки без каталога вакансий. Реквизиты, адрес и контакты не выдуманы.

Видео: «Bienvenido a Kompas» — 40,1 с, «Tu primer día» — 44,6 с. Готовые MP4 и обложки включены в `public/media/`; отдельные проекты производства видео в этот репозиторий не входят и для запуска сайта не нужны. Видео не воспроизводятся автоматически и используют `preload="none"`. При запуске одного ролика другой останавливается.

## Запуск

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 4173 --strictPort
```

Сборка: `npm run build`. Статические файлы находятся в `dist/client`; локальный просмотр собранной версии — `npm run preview`. Сборка также подготавливает Worker для Sites.

## Приём заявок через Cloudflare и Resend

Код обработчика находится в `application-worker/`. Он принимает только запросы с разрешённых адресов сайта, проверяет поля, отсекает простые автоматические отправки, сохраняет заявку в D1 до отправки писем и повторяет недоставленные письма каждые пять минут. Повторная отправка одной заявки не создаёт дубликаты. Предварительный технический срок хранения — 30 дней; до запуска его нужно подтвердить и при необходимости изменить переменной `RETENTION_DAYS`.

До рабочего запуска нужны:

1. Cloudflare D1 с применённой миграцией `application-worker/migrations/0001_create_applications.sql`.
2. Проверенный в Resend домен отправителя и секрет `RESEND_API_KEY`.
3. Почта получателя в секрете `APPLICATIONS_TO_EMAIL` и адрес отправителя в `APPLICATIONS_FROM_EMAIL`.
4. Адрес развёрнутого Worker в `VITE_APPLICATION_API_URL` при сборке сайта.
5. Согласованный текст об обработке персональных данных, подтверждённый срок хранения и полная тестовая заявка.

Примеры переменных находятся в `.env.example` и `application-worker/.dev.vars.example`; настоящие ключи и адреса в Git не добавляются. Серверные проверки запускаются командой `npm run test:applications`. Пошаговая настройка и команды развёртывания описаны в `application-worker/README.md`.

## Изменение содержимого

Для редактора: **[пошаговый гайд на русском](docs/editor-guide-ru.md)** · **[версия PDF](output/pdf/kompas-editor-guide-ru.pdf)** · [вход в Pages CMS](https://app.pagescms.org/sign-in).

В разделе **Página principal** редактируются тексты, изображения, оформление двух видеокарточек и пять шаблонов блоков. В разделе **Aviso y pestaña del navegador** редактируются объявление, название вкладки и описание страницы.

Контент хранится в `src/content/site.json`. Перед каждой сборкой `npm run validate:content` проверяет обязательные поля, пути и форматы изображений, размер загружаемых файлов, уникальность блоков и безопасные назначения кнопок. Повреждённый контент не публикуется.

После сохранения в Pages CMS изменение попадает в `main`. Workflow `.github/workflows/publish-site.yml` запускает тесты, собирает сайт и автоматически обновляет `gh-pages`. История остаётся в GitHub, поэтому предыдущую версию можно восстановить. Публичной панели управления на самом сайте нет.

Для первого входа владелец репозитория открывает `app.pagescms.org`, входит через GitHub и устанавливает Pages CMS GitHub App только для репозитория `KazakbayZhanibek/er`. Клиента можно пригласить в Pages CMS по email как редактора: он может менять контент и медиа, но не `.pages.yml` и не настройки доступа.

## GitHub Pages

Предпросмотр: [kazakbayzhanibek.github.io/er/](https://kazakbayzhanibek.github.io/er/).

Основной домен: [kompastrabajo.com](https://kompastrabajo.com/). Файл `public/CNAME` сохраняет привязку домена при каждой новой публикации.

В `main` хранятся исходники. Pages должен публиковать ветку `gh-pages`, папку `/ (root)` — в неё помещается готовая сборка из `dist/client`. Исходный `index.html` из `main` напрямую публиковать нельзя: он требует сборки Vite.

Каждое изменение в `main`, включая сохранение через Pages CMS, автоматически запускает публикацию. Для ручного выпуска команда `npm run deploy:pages` собирает сайт и отправляет результат в `gh-pages`. Она использует отдельный временный индекс Git, сохраняет историю публикаций и не переключает рабочую ветку. Публикация не подключает отправку или хранение заявок. Пути к ресурсам относительные, поэтому сайт работает и в корне, и по адресу `/er/`.

## Проверки и материалы

- Проверки сборки и упаковки: `npm run build` и `npm run test:sites`.
- В браузере проверены формы, редактирование данных, закрытие с клавиатуры, воспроизведение обоих видео и отображение на ширине 320, 768 и 1440 пикселей. Внутренние рабочие заметки и снимки проверки в репозиторий не включены.
- `public/images/ASSETS.md` — промпты и происхождение изображений. PNG — исходники; WebP — версии для сайта.
- `public/media/ASSETS.md` — происхождение готовых видео и обложек.
- Палитра: `#F3E8D7`, `#332923`, `#A84631`, `#FBF8F2`.
- [Newsreader](https://fonts.google.com/specimen/Newsreader) и [Manrope](https://fonts.google.com/specimen/Manrope) поставляются локально через Fontsource.
- [Phosphor React](https://github.com/phosphor-icons/react) используется для стандартных интерфейсных иконок.

## Для рабочего запуска

Остались адрес получателя, ключ и проверенный отправитель Resend, создание D1 и развёртывание Worker, домен и согласованные тексты об обработке данных с реальными данными компании. После настройки нужно проверить сохранение заявки, доставку письма менеджеру и испанского подтверждения кандидату, затем включить адрес API в производственной сборке. Бренд Kompas, испанский язык, вся Испания и формат общих заявок уже подтверждены; каталог вакансий и публикация деталей договора сейчас не нужны.
